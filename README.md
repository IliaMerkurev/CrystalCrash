
### Adaptive rendering (prototype/0.5)
The loading warmup measures five GPU-completed representative scene renders after shader compilation (including glass, reflection and effect warmup meshes). Desktop Auto selects an aspect-preserving 0.9 / 1.4 / 2.0736 megapixel drawing-buffer budget; coarse-pointer mobile devices conservatively start at Low. Automatic floor reflection choices are256 /512 /1024. Scene resolution and mirror quality are independently overridable. CSS/UI stays native size. The reflection uses a tight nine-texel weighted filter; its quality still needs device visual judgment, particularly at256. The transmission prepass reuses the last completed ACES floor reflection instead of rendering the scene again with mismatched tone mapping. The visible floor refreshes normally every frame.

Test includes Auto/Low/Medium/High and reports actual buffer dimensions, reflection size and recent frame time. Auto can lower one tier after sustained slow visible gameplay, with hysteresis and cooldown; it does not oscillate upward. Hidden tabs/menus do not count. Loading measurements are a heuristic, not an iPad FPS guarantee. Physical timestep remains90Hz.

Intact shells now use one closed box collider with explicit mass/COM/inertia matching the previous six equal-mass panels. The first valid damage event rebuilds the exact surviving fracture colliders, including airborne hits. Three deterministic fracture patterns per shape/tier are cached in a bounded32-entry LRU; each original owns independent graph state and cloned geometry. Preparation happens while constructing an arena, not on first impact. Sleeping bodies skip redundant JS transform/velocity reads; ordinary Rapier wake-up and precise damaged collisions remain active. No changes to90Hz physics timing or bonus rules.

### Independent performance controls
Test → Performance persists scene Auto/Low/Medium/High, floor mirror Auto/Off/128/256/512/1024, reflected cubes, cube environment lighting, reflected particles, debris environment lighting, shadows Off/512/1024, gate transmission, and an optional live diagnostics overlay. Particle reflections and debris environment lighting both remain enabled by default. Off stops the floor scene pass; object exclusions are scoped and restored after that pass. Environment Off uses a prewarmed shader variant with cubemap sampling compiled out, retaining other material hooks. Gate transmission uses fixed half-resolution rendering across scene presets for cleaner comparisons; disabling it uses alpha glass instead.

Diagnostics show gameplay FPS/frame time, CPU physics and render submission time (not GPU execution time), complete-frame draw/triangle counts, bodies/colliders and actual resolutions. Updates are capped at4Hz. Auto targets60FPS and can lower a tier after a1.5s sustained failure window, with2s initial/5s subsequent cooldown; manual choices are not overwritten. The128 mirror uses a tight coherent filter and a rougher floor coat, not separated ghost-image samples.

Upcoming targets render as single-material simple boxes without shadows or animated bonus cores. Detailed next-arena geometry is prepared during arena loading and stays hidden; gate readiness fades it in over0.55 simulation seconds, so transition causes no geometry-construction spike. No additional physics arena or physical timing changes were introduced. Device visual quality and iPad performance remain user-verification items.

### Built-in iPad/browser profiler
Test → Profiler closes the blurred menu and keeps gameplay running behind a compact, unblurred diagnostic overlay. Expand Controls to record an 8-second baseline, change one visual switch, and record a comparison. Paused, hidden-tab, menu and transition samples are excluded. Copy or download the text report; device/browser support can limit clipboard/download behavior.

CPU buckets are exclusive: exact Rapier `world.step`, contact/fracture processing (nested calls counted once), remaining simulation/effects, render preparation/particles/UI, and WebGL submission. CPU submission is not GPU execution. Asynchronous GPU queries are used only when supported, never force a synchronization, and are labeled unavailable otherwise; their delayed samples are not added to CPU totals. RAF intervals include scheduling/compositor time. Median/p95 and the timeline are observational: two runs may have different destruction/ball workloads, so the report includes scene counts/settings and does not assert causal FPS gains.

Session-only A/B switches cover area lights, HUD blur, inner glass, clearcoat, cube normal maps, transparent floor coat, main-view particles/glow, decorative rail blocks and upcoming visual decks. They preserve gameplay/physics and revert when Profiler closes. Existing saved quality choices remain independent. Shader-changing comparisons settle before recording. Physics remains 90 Hz. Shadows Off also removes the separate ball contact disk.

### Mobile rail-light default (v82)
Area lights are now off by default on phones/tablets, including desktop-UA touch iPads. Test → Performance → Area lights persists an explicit override; older stored settings without this field adopt the device default. Desktop keeps them on. The four area emitters are excluded from scene traversal during drawing, including the mirror, rather than set to zero intensity. Existing directional/hemisphere/environment/emissive lighting remains unchanged. Profiler starts from this saved baseline, permits temporary A/B changes, and restores the saved choice on close. Auto quality never changes this preference. Focused settings/visibility tests and build passed; new iPad visual validation is not claimed.

### Cleanup, fixed starts and lighting controls (v83)
When every surviving original has recorded damage, cleanup applies one ordinary one-unit strike each simulation second, keeping the same original until it is gone. Remaining originals enter zero-automatic-score cleanup; direct player/power strikes restore normal scoring for their targets. Cleanup Bomb drops carry that zero-score provenance. Drops still occur once and the gate waits for actual empty structure state. Pause/aim slow follow simulation time.
Initial and post-transition balls stay at the fixed start until a successful main launch. Direct catch/aim works immediately; empty-space attraction does not relocate the start. Transition resets gestures.
Test has collapsible Arena, Bonuses, Graphics, Lighting and Shadows sections; Profiler remains at the top. Lighting exposes Fill lighting (hemisphere/cool fill), Area lights Auto/Off/On and cube/debris environment highlights. The directional key remains available for independent shadows. Legacy explicit area booleans migrate to manual On/Off. Auto stays off on mobile or unavailable/disjoint GPU timing. Desktop qualification requires 30 asynchronous samples with GPU p90 below8ms and frame p90 below18ms; two later 30-sample windows over12ms GPU or22ms frame latch it off. Sampling runs every fourth gameplay frame without GPU waits; manual choices win.
Shadows Auto selects one batched feathered contact-shadow draw when area lights are off, or filtered directional shadows when enabled. Explicit Off remains empty; Soft contact/Low/High remain independent of area lights. Sphere contacts are circular, cubes use rounded-square approximations with altitude spread/fade; these are ground cues, not inter-object occlusion. Dynamic PCF shadow radius is3.5. The old hard ball disk is never displayed. No new device FPS or visual validation is claimed; focused scheduler/provenance/input/settings/shadow resource checks and production build passed.
